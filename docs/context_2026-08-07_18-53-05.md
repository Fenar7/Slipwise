## 4. Diagnostic Key Resolutions & Engineering Accomplishments

### A. Next.js Edge Runtime Crypto Crash Refactor
- **Issue**: Importing Node.js native `crypto` and `Buffer` inside `src/lib/mfa/token.ts` and `src/lib/totp/challenge-session.ts` crashed Next.js Edge Middleware because Node.js APIs are incompatible with V8 Edge Isolate runtime.
- **Fix**: Refactored both files to pure W3C Web Standard APIs (`globalThis.crypto.subtle`, `TextEncoder`, `btoa`, `atob`). Updated all callers across API routes, server actions, and Vitest test suites to `await` signatures. All 41 Vitest unit tests pass 100%.

### B. Turbopack NTFS Junction Point OS Error 5
- **Issue**: Moving project files to Drive F left stale cross-volume NTFS junction points inside `.next\dev\node_modules\`, causing Turbopack to panic with `Access is denied (os error 5)`.
- **Fix**: Purged `.next` directory. Turbopack automatically recreates clean Drive-F junction points on startup.

### C. Signup `TypeError: Failed to fetch` & Docker Networking
- **Issue**: Submitting signup at `http://localhost:3001/auth/signup` failed with browser `TypeError: Failed to fetch`.
- **Root Cause**: Local Supabase API Gateway (`http://127.0.0.1:55321`) was offline due to stale volume mounts referencing Drive C (`C:\...\supabase\.temp\...`) and Docker Desktop `vpnkit` port forwarding failures (`connection refused`).
- **Fix**: Reset WSL subsystem (`wsl --shutdown` & `wsl --unregister`), generated `secret-0` key for `pgsodium` at `supabase/.temp/start-secrets/supabase_db_slipwise-backend/secret-0`, and bound fresh containers to Drive F.
